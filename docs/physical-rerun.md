# 实物模型输入与 Rerun 回放

模型页按所选执行profile中的相机输入生成源预览；实际预测输入由编码器在
调用predictor前取出，同一次推理的图像和小型状态向量随诊断结果记录。
当前ACT显示`image`和`wrist`的RGB 256×256图，包含真实去畸变/缩放结果，
不是另写一套近似预处理。相机源使用既有MJPEG长连接，实际预测输入使用
multipart PNG长连接；只在新帧到达时更新，不定时替换图片URL或触发加载动画。
浏览器在canvas中保留上一帧，HTTP错误、流结束或5秒无新帧时自动重连，
重试间隔从0.5秒退避到最多8秒，并显示断开状态。已结束回合的模型输入
不无限重连；组件移除时取消网络请求和计时器。
模型输入只按实际推理频率更新，不插帧冒充连续相机采集。
画面带观测序号和年龄；未推理、停止或过期不能
当作实时画面。源预览走既有视频服务，不重新占用摄像头。

外部policy profile配置：

```json
{
  "rerun_recording": true,
  "policy_kwargs": {"diagnostic_inputs": true}
}
```

这两个字段须并入现有profile，不能用上面的片段覆盖整个profile。
运行环境需按需安装`rerun-sdk==0.42.0`；可以使用独立依赖
目录，不替换机器人控制环境。默认仍是原摘要模式，仅显式开启才保存RRD。

每个回合在已有episode目录生成`recording.rrd`、`summary.json`、
`rerun-status.json`和最新输入的少量PNG/manifest。记录从准备到结束，包含：

- 两路相机源、帧序号、接收时间、有效性；相机源在RRD中为JPEG质量90，
  不宣称原始无损。模型编码输入另以原值Tensor记录，最新网页输入PNG无损。
- 实际编码输入、原始预测动作块、解码动作块及对应观测序号/源帧时间。
- 实测关节位置/速度/力矩、TCP反馈、实际提交目标、重力/积分诊断。
- 准备阶段、路点、模型身份/profile、推理时延、到时/操作员停止/异常原因、失能回执。

`episode_time`与`host_monotonic`时间轴明确区分事件发生时刻与相机接收时刻。
这是主机接收时间，不是曝光同步，也不包含物体真值或未安装的力/触觉数据。
不能仅凭关节电流推断真实接触力，也不能把名义FK当成实测外部定位。

记录使用有界后台队列，编码/磁盘操作不在CAN线程执行；队列溢出或记录失败
会明确报告并走原有停止清理，不会静默丢帧后仍宣称记录完整。新增诊断会有
额外CPU、IPC与存储成本，离线验证不代替现场时序验证。

实物CLI借用HTTP相机时，用单个后台读取器持续替换最新一批帧，控制循环只
读取缓存，不等待HTTP或PNG解码。缓存不修改接收时间戳；读错会锁定为错误，
相机代际/身份变化不能在策略执行中静默重连。采集失败与陈旧帧仍触发原保护。
合并观测时先读传感器缓存，最后读机器人最新反馈，TCP的150ms门槛不放宽。

结束后页面可下载本轮`.rrd`。将文件传到Rerun查看器所在机器，用MCP打开
文件并读取schema/时间轴，再逐帧检查；数值可由查看器catalog通过Python精确
查询。MCP控制的是查看器，不是机械臂。历史只有摘要的回合无法补造图像。

准备提速属于安装级外部profile修改：本轮使用0.5 rad/s、1.5 rad/s²，原路径、
路点、到位容差、等待上限、硬件保护不变。实际总准备时间还包含稳定等待，
不承诺恰好减半，不自动改写其他安装的速度。
笛卡尔执行器的`preparation_velocity_rad_s`必须与准备速度一致；省略时沿用
`velocity_rad_s`。两者分开设置，避免准备提速同时改变模型执行时的关节速度。
