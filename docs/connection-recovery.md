# 网页连接恢复

缺少 CAN 设备或暂时无回复不应阻断统一网页。模型页在后台复用现有 `ArmConnection`
只读查询与退避重连，显示等待、只读就绪或控制占用状态。断连后按 1、2、4、8、16、
30 秒退避，之后最多每 30 秒再试；停止可中断等待。页面轮询不等待 SocketCAN 的
连接/关闭操作。配置文件替换、服务暂不可用等状态读取错误会保留页面与停止按钮，
后续轮询继续；状态 API 用可重试的 503 回应，不伪造成功。

## 恢复连接不等于恢复运动

- 自动重试只使用查询报文；不加载模型、不使能电机、不移动、不归位，也不重放旧动作。
- 已收齐八个电机的新鲜反馈、均未使能且总线健康，才显示只读就绪。电机故障、错误计数、
  不匹配的配置和陈旧反馈不会被当作就绪，也不自动清错、写零位、改波特率或重置总线。
- 启动策略或归位仍由操作员点击。CAN 等待时按钮不可用；即使界面和断连发生竞态，
  后端仍检查连接，真实控制会话再次执行原有 preflight。
- 运动交接前，服务管理器先关闭只读查询并释放原有总线锁；读线程未退出就拒绝交接。
  这同时覆盖模型、归位以及平台管理的其他 motion 服务。不停止或接管外部控制器。
- 运行中失联依旧触发原有超时、停止和失能清理。连接恢复不自动使能、续跑或返程。
  只有本轮正常清理后，空闲状态才重新开始只读观察。未确认清理仍阻止新运动。
- attach-only 和显式仿真平台不启动这一套实物查询。所选模型的机器人 profile 决定
  接口名和左右臂映射；浏览器只能选已注册模型，不能提供总线名、路径或系统命令。

## 系统配置与启动入口

只读重连不能替代正确的 SocketCAN/USB/供电配置。设备不存在、接口 down 或 bus-off
时网页仍可用，但不会擅自执行 sudo、`ip link` 重配或重启系统服务。按既有个人级
系统配置恢复接口后，查询自动重试。真实电机故障仍需现场处理。

维护的 `run_platform.py` / `openarm-runtime platform` 不要求 CAN 先连接成功才启动网页。
如果个人的旧包装脚本在启动网页**之前**检查 CAN 并直接退出，也要同步移除这层
前置硬拦截；不能只更新网页代码就宣称旧包装入口已修好。机器路径、服务名、sudo
权限和设备规则仍放在个人配置，不写入共享仓库。

本轮不增加运动服务的自动重启。现有相机等独立服务启动失败仍被隔离为模块状态，
不应拖垮网页；需要重试时沿用原有模块激活/恢复入口。不能把 TCP 端口可达当作
硬件健康或实物执行成功。离线断连/恢复检查也不替代真实 USB 热插拔验收。
